# Objekte (Teil 1, #92) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mehrere Objekte in einer Installation. Jede Abrechnung, jedes Mietkonto, jede
Verbrauchs- und Steuerübersicht gilt je Objekt. Wer ein Haus hat, merkt nichts.

**Architecture:** Neue Tabelle `properties`, dazu `property_id` an `units`, `meters`,
`cost_items` und `closed_settlements`. Der Rest erbt das Objekt. Zwei erzeugte Drizzle-Schritte
tragen die Migration: 0001 legt die Spalten ohne Pflicht an, samt Datenanteil (Objekt 1). 0002
macht sie per Neubau zur Pflicht. Die Berechnung bleibt unverändert, `narrowToProperty` in
snapshot.ts ist die einzige Stelle, die auf ein Objekt eingrenzt. Die Routen nehmen
`?property=`, und bei genau einem Objekt geht es auch ohne.

**Tech Stack:** Node 24 (TypeScript ohne Build), Express 5, Drizzle ORM 0.45 über
`sqlite-proxy`, drizzle-kit 0.31, `node:test`, React 19 + Vite, vitest.

**Spec:** `docs/superpowers/specs/2026-09-30-objekte-design.md`

## Global Constraints

- **Bezeichner englisch.** Kommentare, Oberflächentexte, Fehlermeldungen, Testnamen und
  Commit-Nachrichten deutsch.
- **Geld in Cent als Integer.** Datum als ISO-Zeichenkette, UTC, inklusive Grenzen.
- **Imports im Server mit `.ts`-Endung.** Reine Typimporte als `import type`. Kein `enum`,
  kein `namespace`, keine Parameter-Eigenschaften (`erasableSyntaxOnly`).
- **Migrationen:** Aufbau immer mit `npm --prefix server run db:generate` erzeugt, nie von
  Hand. Daten dürfen vor der Veröffentlichung als Anweisungen an einen erzeugten Schritt
  angehängt werden. Ein veröffentlichter Schritt wird nie geändert.
- **Eingefrorene Dateien** `server/src/legacy/{schema,write,migrate}.ts` bleiben
  unverändert. Ihre Prüfsumme steht in `legacy-schema.test.ts`.
- **Wer einen Server startet,** setzt `NKA_DATA_DIR` (Wegwerf-Ordner), `CI=1` und
  `NKA_UPDATE_URL` (geschlossener Port). Die Vorlagen sind `startServerIn` und
  `startServerRaw` in api.test.ts.
- **Kein neues Pflichtfeld in der Oberfläche.** Der Objekt-Umschalter erscheint nur bei mehr
  als einem Objekt.
- **Kennung von Objekt 1 aus dem Umstieg:** `'objekt-1'`.
- **Objektarten:** `'mfh' | 'etw' | 'efh' | 'sonstiges'`, Voreinstellung `'mfh'`.
- **Vor jedem Commit** `npm run typecheck`.

## Review Focus

1. **Zeilenreihenfolge nach dem Neubau in 0002.** read.ts liest nach `rowid`. Die Reihenfolge
   von Wohnungen, Zählern und Kostenpositionen muss nach der Migration dieselbe sein, sonst
   springt die Anzeige, und bei gleich datierten Ablesungen gälte ein anderer Stand. Test in
   Task 1.
2. **Frische Datenbank ohne Einstellungszeile.** Objekt 1 muss trotzdem entstehen, mit leerem
   Namen und leerer Adresse, und die erste Wohnung muss sich ohne `property` anlegen lassen.

   Test in Task 6.

  ```ts
  export function narrowToProperty(source: PropertyScopedSource, propertyId: string): SnapshotSource {
    const units = source.units.filter((u) => u.propertyId === propertyId)
    const unitIds = new Set(units.map((u) => u.id))
    const tenancies = source.tenancies.filter((t) => unitIds.has(t.unitId))
    const tenancyIds = new Set(tenancies.map((t) => t.id))
    const meters = source.meters.filter((m) => m.propertyId === propertyId)
    const meterIds = new Set(meters.map((m) => m.id))
    return {
      units,
      tenancies,
      costItems: source.costItems.filter((c) => c.propertyId === propertyId),
      meters,
      readings: source.readings.filter((r) => meterIds.has(r.meterId)),
      payments: source.payments.filter((p) => tenancyIds.has(p.tenancyId)),
      closedSettlements: source.closedSettlements.filter((c) => c.propertyId === propertyId),
    }
  }
  export function snapshotFor(source: PropertyScopedSource, propertyId: string, year: number): Snapshot {
    return { ...snapshotOf(narrowToProperty(source, propertyId), year), propertyId }
  }
  ```

  keine Fehlermeldung, sondern eine Verteilung über zwei Häuser. `Snapshot.propertyId`
  ergänzen, `snapshotOf` gibt `propertyId: null` zurück.
